# 纳气期蛊反噬、蛊损失与本命蛊保护设计

日期：2026-10-29  
适用项目：独立升仙模组。该设计只定义游戏映射，不开放普通升仙 readiness。

## 目标

在纳气阶段为服务端确认的真实蛊催动累计反噬压力。达到游戏化阈值时，损失本次催动的一只蛊；与已绑定本命蛊内容指纹相同的蛊都受保护。扩大真实催动入口的精确观察，未知入口不能触发损失。

## 原著依据与游戏化边界

- CANON-008 记述纳气期间用蛊会遭反噬，并记有方源损失大量凡蛊；方正在升仙托举、心神脆弱时催蛊遭反噬，蛊虫随即毁灭。
- GAP-004 未给出通用阶段边界、逐次概率、损失目标和本命蛊保护方式；不得声称下列数值是原著规则。
- 本设计把可观察窗口固定为 `Phase.ABSORBING`，以通过验证的催动事件累积压力。默认每 8 次确认催动触发一次损失，阈值为服务器游戏参数，可配置范围 1–64。
- 每次达到阈值时，只尝试损失触发阈值的那次催动所用的一只蛊；移除一个 stack count。若此蛊受本命蛊保护，阈值消耗但不损失另一只蛊。不额外添加玩家伤害或异常效果。

## 催动事件语义

- 仅服务端 `ServerPlayer`、当前 `first` 升仙会话处于 `ABSORBING`、并且上游精确分支已确认接受的事件可加压。
- 事件至少要有上游已扣除/改变真实资源的证据；按键收包、物品 wrapper、冷却 helper、手持物或单次 `inventoryTick` 不等于催动。
- 对延迟结果的入口，若无法确认结果已产生，则不触发损失；本体资源已扣但未有确认结果的观察不计入压力。
- 当前 C/V/X/Z 杀招观察以实际变更的 `_NaiJiu` 槽及其 `ItemStack` 为目标；其他入口须逐条核实成功分支、消耗对象和结果时点后才可注册。
- 被动维护只在能辨认一次性有效触发时计一次，不按持续 tick 重复累计。

## 压力、损失与保护

- `shengxian:gu_backlash` 玩家持久数据按升仙 session UUID 绑定，保存压力、阈值快照、顺序号和最近损失回执；新 session 从零开始，服务器重启后沿用已有状态。
- 每个确认催动加 1。达到冻结阈值时，按当前催动所携带的精确存储位置和堆栈身份损失 1 个该蛊；剩余压力扣除阈值。若上游正常催动已经消耗该堆栈，或该堆栈不存在，则不再损失其他蛊，阈值仍被消耗。
- 本命蛊保护同时比对会话已绑定指纹和上游 `PlayerVariables.BenMingGu` 镜像；采用现有规范化内容指纹（计数与 DAMAGE 不参与）。所有内容指纹相同的副本都保护，不把它伪称为唯一实例 ID。
- 如本命蛊身份、目标堆栈/槽位或事件归属无法明确核验，损失事务 fail closed：不销毁物品、不猜测其他候选蛊，并把本次阈值消费结果写成可诊断回执。
- 压力、玩家回执和物品数量变化写在同一玩家存档 NBT 中；保存后核验 UUID 玩家文件，单人房主另核验 `level.dat/Data/Player`。保存失败或文件两侧无法一致核验时隔离，不自动重试第二次损失。

## 入口覆盖范围

- 当前 JAR 指纹仍为 `b6d314d3810b8bc5fcfdbc4f588db8721f0efdfc14d27a0a06d88143a01fe2bc`。已有 8 个静态钩子：月光蛊、白象蛇蛊、哀别持、定蛊二号四个接受分支，以及 C/V/X/Z 四个实际耐久变化观察点。
- 静态审计发现 154 个 rank-tagged 物品各有 `use` 与 `inventoryTick` wrapper、14 个杀招按键候选、1,881 个含信号 Procedure 方法，以及 3,116 个未分类 item-entry 候选；这些数量不代表接受催动或覆盖率。
- 实施时扩展精确接受/完成分支清单及 hook verifier。仅已验证入口参与规则；未分类方法和无法证明成功语义的入口不产生压力或损失。禁止用全局右键、网络收包、通用 wrapper、全部 inventory tick 或冷却写入代替成功观察。
- 在全体入口完成核验、持久事务回归与隔离运行验收前，`AscensionReadiness.implementedCapabilities()` 继续为空，`GU_BACKLASH` 不得开放。

## 验证要求

- RED/GREEN 覆盖：仅 ABSORBING 计数；拒绝分支和被动 tick 不加压；延迟/未完成入口不损失；每 8 次（或配置阈值）恰好一次损失；压力按 session 持久化。
- 本命蛊测试覆盖规范化指纹、损伤/数量差异、内容相同副本保护、不同组件不误保护、绑定缺失或来源不明时 fail closed。
- 持久化测试覆盖 player data 与单人 host NBT 读回、回执重复、保存失败、崩溃边界、损失次数不重放，以及 `PlayerVariables` 杀招槽和普通背包目标的精确定位。
- Hook verifier 绑定上游精确 JAR 哈希、类描述符、分支成本信号、注入位置和目标栈解析；无法静态证明的入口留在未分类清单。
- 离线测试与源码编译不能替代真实玩家交互。真实死亡/损失、客户端同步、多人、重登和崩溃恢复只在单独隔离世界验收，不触碰用户存档。
