# 首批代表仙蛊设计（增强版）：定仙游、人如故、江山如故

日期：2026-10-30  
状态：用户已批准增强版，并明确要求开始开发（2026-10-30）。

## 目标与依据

第一批交付三只实际可持有、可右键催动的仙蛊，分别提供移动、伤势恢复、有限地形修复。三只均可反复使用，扣青提仙元并受冷却限制。

增强后的默认玩法：定仙游保存八个落点并允许移动、受伤期间蓄力；人如故可救治自身和他人，恢复窗口五秒；江山如故一次最多修复 1024 格，保留十分钟灾毁记录。所有数值仍为游戏参数。

- [第四卷第二章《愧疚的太白云生》](https://www.hetushu.com/book/7640/5345889.html)：人如故恢复一瞬之前的状态；江山如故作用于山水，家具不在作用范围。这是转载正文，不是官方校订版。
- [第四卷第二十八章《一战黑城》](https://www.hetushu.com/book/7640/5345915.html)：定仙游完全催动需要三息。[第四卷第二百八十三章《夜叉章鱼和口蚯》](https://www.hetushu.com/book/7640/5346170.html)记述记住目的地景象后催动定仙游脱身。
- 本体 JAR 中已有五转人如故蛊与蛊方；新增物品使用 `shengxian` 命名空间和“仙蛊”名称，独立于本体五转物品，不替换其程序。
- 下述秒数、仙元费用、冷却、范围、生命值映射和灾毁留景均为游戏规则，不作为原著定量结论。

## 实现方式与边界

采用共享的服务器催动流程，并把三种实际能力分开实现。相较于只追加命令目录，这种方式具备真实物品与操作反馈；相较于直接套用本体五转人如故程序，它能独立扣仙元、保留仙蛊并控制恢复范围。

- 平台为当前项目的 Minecraft 1.21.1 / NeoForge 21.1.263 / Java 21。
- 新三只要求玩家有 `IMMORTAL` 会话、已形成仙窍、本体转数至少六转，且持有与本人及当前 session 匹配的仙蛊物品和世界账本记录。本体转数只读。
- 仙元从现有仙窍账本扣除；普通升仙的 readiness 保持关闭。
- 秒数均按 20 server ticks 映射；费用、冷却和范围使用服务器参数，每次催动冻结当次取值，调整配置不缩短已经开始的冷却。
- 不增加炼成、饲养、世界唯一性或本体仙元字段。继续沿用管理员发放；当前会话账本的持有规则不宣称世界唯一性。
- 保留原排难仙蛊及其原有命令行为。新三只不走“使用一次就消耗蛊”的账本路径。

## 共用物品与账本

- 物品 ID 为 `shengxian:ding_xian_you`、`shengxian:ren_ru_gu_immortal`、`shengxian:jiang_shan_ru_gu`；不可堆叠。
- `/shengxiangu grant <player> <id>` 先提交持有记录，再向目标背包交付绑定物品；背包满则保留可恢复的交付记录，不把物品扔在地上。
- 物品自定义数据绑定 owner UUID、session UUID、gu ID。服务器账本同时验证持有权；复制或转交一个绑定物品不能获得新的持有权或独立冷却。
- `/shengxiangu recover` 根据有效持有记录补交本人缺失的物品投影。副本仍共享同一持有记录、仙元和冷却，不构成第二只独立仙蛊。
- 三只使用专属的小型立体物品模型：碧蝶、虹蝶、山水瓢虫。模型用项目 JSON 元素和现有基础纹理表达，配中文/英文名称与明确工具提示。
- 命令 `list/status/use` 与物品共用服务器校验；新三只从命令催动时也要求持有匹配物品。列表展示用途、费用、持有与冷却，不要求玩家理解内部证据编号。
- 冷却按服务器主世界游戏时间持久化；重登不清空。计时异常、未知版本数据或身份冲突时拒绝催动并保留记录。

## 定仙游

- 每个 session 最多保存八个亲自到达的安全落点。潜行右键空气切换当前槽位；潜行右键方块，把玩家当前站立位置记录/覆盖到当前槽位。记录维度、位置、朝向和周围固定范围的方块状态摘要，动作栏显示所选地点。
- 普通右键持续蓄力，默认 60 server ticks，保留三息的原著依据。蓄力期间允许走动、飞行和受伤；松开使用键、切换物品、骑乘、死亡、换维度或掉线取消。取消发生在扣费前。
- 结束蓄力后重新核验持有权、仙元、冷却、目的地维度、世界边界、落脚地面、两格头部空间和周围景象摘要。
- 只加载标记周围有限的目的地区块以完成落点检查，不维持长期强加载。目的地缺失、景象变化或落点不安全时失败且不扣费。
- 标记在仙窍内时，必须重新核验当前地块归属与访客/护道权限；失去权限后旧标记不能绕过保护。
- 只传送催动者，不携带骑乘实体或其他玩家。
- 默认费用 3.0 仙元，冷却 10 秒。成功出现身侧盘旋的碧蝶、起点收束与终点展开的蝶光；保持低亮度，传送完成后解除本次累积的摔落距离。

## 人如故

- 普通右键恢复自身；潜行右键以服务器射线选择同维度 24 格内可见的在线玩家进行救治。目标不要求拥有仙窍或仙蛊；费用由催动者支付。射线没有有效玩家目标时拒绝本次救治，不改成对自己使用。
- 服务器为在线玩家逐 tick 保留最近 100 ticks 的有界健康记录。取窗口内最高的有效生命值及其对应状态作为恢复目标，并钳制到目标当前最大生命值；至多回溯五秒。
- 同时处理这个短时记录明确证明为新发生的燃烧、中毒和凋零：只有所选历史状态不存在该项伤害状态时，才移除当前对应的燃烧或原版中毒/凋零。不复原已结束的旧状态，不移除其他本体效果。
- 仅对仍存活且存在实际可恢复内容的目标生效。没有近期记录、没有生命收益且没有符合条件的新伤害状态时不扣费。
- 成功后重设该目标的历史基线；同一目标共享两秒受治间隔，避免多只副本或多名施术者反复兑现同一段旧伤。不同目标各自计时。
- 不回退位置、物品、真元、寿元、失窍、饥饿或吸收生命，不恢复最大生命属性，不提供复活。
- 记录在目标死亡、clone、掉线或换维度时清空；施术者 session 变化会清除其未完成操作。其他玩家救治同时锁定施术者与目标，核验距离、可见性和两者存档身份后才执行。
- 默认费用 2.0 仙元，催动者冷却 3 秒。使用后保留仙蛊，五色蝶影向目标聚合，身侧显示短促的伤势回卷粒子；不增加全屏亮度。

## 江山如故：有限灾后地形修复

直接恢复已产生掉落的方块会复制材料。第一批采用明确的游戏规则“灾毁留景”，在用户主动开启后以不掉落的灾毁记录换取复原能力。

- 潜行右键切换留景，默认关闭。仅在本人已形成的仙窍地块内、本人在线且有效持有该仙蛊时记录爆炸损毁；不会替其他地块记录。
- 开启状态及“被记录的自然材质爆炸损毁不掉落材料”在物品提示和切换反馈中明确展示。过期、离线或重启会清空未使用的短时留景；这些记录不产生材料补发。
- 固定白名单只含普通、非重力、无方块实体的地形材质，例如石头、泥土、草方块、砂土、灰化土、深板岩、凝灰岩、泥巴和黏土块。容器、矿物、机器、功能方块、流体与方块实体不记录；玩家搭建的同白名单材质也按地形材质处理，不声称能辨认所有人工建筑。
- 只对确实走过已审计爆炸销毁分支、且该次物品/经验掉落被抑制的白名单方块建立可用记录。记录容量满、归属不明或无法确认无掉落时，维持原爆炸行为并不生成可恢复记录。
- 本地字节码已确认 `BlockDropsEvent` 不能单独覆盖爆炸掉落：`BlockBehaviour.onExplosionHit` 有自己的掉落 consumer。因此实现需要针对当前版本的精确爆炸分支做范围很小的注入，并增加字节码校验；不能用通用破坏事件假定无掉落。
- 每位玩家最多保留 8192 个位置、全服最多 65536 个；记录保留十分钟。容量满时不丢弃其他玩家未过期的记录来腾位置，而是让新的爆炸破坏走原掉落流程且不记入可修复记录。相同位置再次被放置或改成非空气时，旧记录失效；相关区块卸载也丢弃其记录。停止服务/玩家离线后不从历史区块推测丢失记录。
- 普通右键修复本人地块内、距玩家不超过 32 格的记录，单次最多 1024 格，按距离与坐标确定顺序。当前仙窍水平地块仍为 16×16；32 格半径覆盖整块地面和附近高度，不能跨越其他玩家的边界。只在当前位置仍为空气、区块已加载、位置不与实体碰撞、权限仍有效时放回原状态，不覆盖新方块、不产生任何掉落。
- 地形以波纹顺序分批复原，每个操作每 tick 最多 64 格，全服每 tick 最多 512 格，多个操作轮流推进；在当前限额下，一次可复原整片仙窍地面的爆炸缺口。开始前冻结有限计划，执行中持续检查目标空气、归属、碰撞和当前维度。
- 每个成功复原的位置立即消费对应记录。取消留景不妨碍使用当前仍有效的已有记录；新破坏不再被记录或抑制掉落。
- 默认费用 5.0 仙元，冷却 10 秒；至少有一个可修复位置才提交扣费。用扩散的土绿波纹、漂回原位的局部尘粒和低沉回响表现复原；视觉粒子与实际方块更新分别限额，不使用全屏闪光。

## 扣费、冷却与中断

- 增加有界的仙蛊运行状态，与仙元余额在同一次世界会话 CAS 写入中保存。升级为 schema 11；schema 1–10 默认迁移为空运行状态，保留旧账本及原始记录。
- 新状态包含固定三种能力的冷却、定仙游八个落点、单调操作序号和最近操作回执。普通催动不向 512 项追加式 effect ledger 无限写键；原持有/损毁计数保持其旧语义。
- `IMMORTAL` 更新门禁只增加明确的仙蛊运行状态/持有变更白名单，仍拒绝任意三气、风险、灾劫、本命蛊或阶段修改。
- 执行前完成全部目标与权限校验，保存具体效果计划和 PREPARED 回执，再原子扣仙元并开始冷却。实际效果完成且核验后才确认 COMMITTED。
- 人如故、定仙游的玩家回执与目标字段保存后核验 UUID 玩家文件；单人房主另核验 `level.dat/Data/Player`。人如故救治他人时，施术者扣费回执与目标受治回执关联同一 operation ID，并分别验证相关加载源。恢复只确认匹配且已提交的结果，不重放历史治疗或传送。
- 玩家回执首次准备和后续推进前也读取各自加载源，核对旧回执及本次涉及的字段；两来源或内存与来源存在无法解释的冲突时，不用 `saveAll` 把差异覆盖成一致。
- 地形修复计划只含有限、明确的位置与原状态；每格写入前重新验证当前空气、权限和碰撞。跨世界区块与玩家存档不宣称原子提交。
- 扣费前失败不收仙元或冷却；扣费后中断且无法证明效果完成时标记 UNCERTAIN，不自动退款、不二次扣费、不自动重放。重启时丢弃短时伤势/地形历史，隔离未确认的效果。
- 状态命令显示不确定操作。权限 2 的管理员可用包含精确 operation ID 的 `acknowledge` 命令接受当前已发生的结果并解除隔离；此命令不恢复生命、不移动玩家、不修方块，也不补发仙元。

## 验证与交付

- 有意义的领域回归覆盖：重复催动只扣一次、冷却/持有拒绝、旧 schema 迁移、可重复仙蛊不损毁、IMMORTAL 仅允许指定字段变化、未知/损坏回执隔离。
- 定仙游覆盖八槽切换与重载、移动/受伤不打断、其他取消条件、落点不安全、景象变化、仙窍权限撤回和传送后摔落距离。
- 人如故覆盖五秒窗口、对他人救治的射线/距离/同维度校验、短时燃烧/中毒/凋零、目标受治间隔、过期、无收益、最大生命变化、死亡/clone、双方回执与已提交后不重放。
- 江山如故覆盖无掉落记录才可恢复、白名单/容量/十分钟过期/边界、单次 1024 格计划、每 tick 和全服更新预算、同一记录不恢复两次、拒绝覆盖新方块、实体碰撞、部分完成和重启隔离。
- NBT verifier 核对玩家与单人 host 回执；精确钩子 verifier 核对爆炸分支和物品/经验掉落抑制条件。物品注册、三份模型、语言键做静态一致性检查。
- 执行 Test、NbtCheck、SourceCheck；可用的隔离运行环境只用于注册/加载与玩家交互验收，准确区分已有运行证据和未验证的客户端效果。真实存档、升版、发行产物和提交不在本轮授权动作中。

## 实施顺序

1. 有界状态、重复使用账本、物品注册与发放/补交。
2. 人如故与专用玩家回执。
3. 定仙游标记、蓄力、落点与权限核验。
4. 江山如故留景、精确爆炸分支与修复。
5. 三种模型/视听反馈、回归、文档与验收记录。

以上为同一批交付，实施中按依赖顺序完成，不把仅有目录项当作仙蛊功能完成。
