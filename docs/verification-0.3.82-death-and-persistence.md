# 0.3.79–0.3.82 死亡动画 + 血池持久化

日期：2026-11-02。用户要求：死亡动画 + 血池持久化。

## 一、死亡动画

模型自带 `death` 片段（2.2 秒），此前摧毁是立即 `discard()`，等于没有死亡表现。

实现：
- `CalamityCarrierEntity` 新增同步字段 `DEATH_TICKS` 与 `beginDying()`。
- **不依赖原版死亡流程**：原版会在 20 tick（1 秒）后移除尸体，会把 2.2 秒的动画截断。改为把血量停在 1、置为无敌，由实体自己在 `tick()` 里累加 `DEATH_TICKS`，满 44 tick 再 `discard()`。
- `CalamityCombatService.destroy`：生物走 `beginDying()`；盔甲架（旧存档形态）仍用爆炸粒子立即移除。
- 渲染器按状态切动画：存活播 `idle`，死亡播 `death`，时间基准为 `DEATH_TICKS/20`。
- 死亡期间攻击循环停止（`tick` 对 `isDying()` 直接清理状态）。

实测（服务端轮询存在性）：
```
16:48:35.936 ALIVE
16:48:36.399 ALIVE
16:48:36.863 ALIVE
16:48:37.327 ALIVE
16:48:37.793 gone
```
即致命一击后约 1.9–2.2 秒才移除，与 44 tick 一致（轮询间隔 0.4 秒，存在量化误差）。

## 二、血池持久化

此前血池只在内存，重启回满。

实现：
- 受伤时把血量写入实体自身的持久数据（`getPersistentData()` 的 `shengxian_carrier_health`），随实体 NBT 一起存档。
- `healthOf` 首次见到载体时按此顺序恢复：内存缓存 → 持久数据 → `LivingEntity#getHealth` → 该类型的满血值。
- 摧毁时把持久血量写 0，避免重启复活。

修复的关键 bug：读档时 `applyVariant` 会把血量重置为满血、并覆盖名牌，导致“存档重启回满”。拆成 `applyVariantBasics`（只设变体/碰撞箱/上限）与 `applyVariant`（生成时用，含回满与名牌），读档只走前者。

实测：
```
受伤后: 独角峥虎地劫 剩余 350.0K HP   （Health = 350000.0）
save-all flush → 停服 → 重启 → 重新连接
重启后: 独角峥虎地劫 · 350.0K HP      （Health = 350000.0）
```
血量与名牌都保留，未回满。
