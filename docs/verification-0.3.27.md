## 深水区多人验收：环境边界确认（未完成，原因如下）

用 smoke 构建（readiness 全开 + TAI_BAI profile，已删除）实际走了一遍普通升仙流程的**服务器侧门禁链**，每一环都正确拦截：

| 步骤 | 结果 |
| --- | --- |
| 转数 6.0/阶段 5.0 | `普通路线要求五转四至五阶段` ——拒（正确： ordinaryFivePeak 要求精确 rank=5.0 且 stage=4.0/5.0） |
| 转数 5.5 | 同上 ——拒（正确） |
| **转数 5.0/阶段 4.0** | 通过资格检查，进入下一道门 |
| 无本命蛊 | `本体没有记录本命蛊` ——拒（正确） |
| 旧 IMMORTAL 会话 | `该空窍已有升仙记录` ——拒（正确） |
| 无会话时 shatter | `Session missing` ——拒（正确） |
| 并发 RCON 双连接 | status/list 无串扰，响应完整 |

**停止原因**：继续往下需要"本体记录本命蛊"，那要求玩一遍本体的本命蛊仪式（`/BenMingGu` 是仪式放置命令，需要 FakePlayer 与特定方块交互），机器人/RCON 链路无法完成本体玩法。**双人对同一载体的并发击退、死亡瞬间并发**都建立在"纳气期会话存在"之上，因此同样受阻。

### 结论

- 升仙模块自己的门禁在真实服务器上逐环验证为**正确拒绝**（本次共 6 类前置拦截实测）。
- 深水区验收需要真人完成本体修炼玩法到纳气期——这是"需要玩家参与"的边界，不是代码缺陷。
- smoke 构建已删除；配置已还原 `UNRESOLVED_ORDINARY`；FlowBot 会话与 playerdata 备份已还原；三端已部署 0.3.27。
