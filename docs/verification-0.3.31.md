# 0.3.31 验证记录：原著个例落地（CANON-009 强催与道痕）

日期：2026-11-01。基线 0.3.29（0.3.30 为同一功能的中间构建，消息文案缺陷已在 0.3.31 修正）。

## 为什么做这一条

"尽可能还原原著"的可行范围受证据约束。本轮先确认了哪些已核规则**尚未实现**，得到四项：

| 已核规则 | 实现状态 |
| --- | --- |
| CANON-012 仙窍内部酝酿另一场天劫地灾（内劫） | 未实现 |
| CANON-013 余气升炼本命凡蛊为仙蛊 | 未实现 |
| CANON-009 强行催动排难仙蛊 → 载体仍被灭、仙蛊自爆、双目爆裂留道痕不可复原 | **本轮实现** |
| CANON-013 护道者干扰血云削弱血雨 | 部分（护道者击退载体已有，削弱未做） |

选了 CANON-009：它是玩家可主动选择的**风险/代价机制**，且原文场景最具体（黑楼兰强催、排难之光、自爆、双目）。

同时确认：福地三档（CANON-006，面积/仙元/时间比区间）与天灾→地劫接续（CANON-009/011，音磬清完才出荒兽）**早已实现**，无需重做。

## 实现

**领域层 `core/XianGuForcedUse.java`**（新，可单测）

```
force(progress, gu, carrierId, strikeUnits) → Result(progress, firstTimeDamaged)
```

- 只接受 `CARRIER_STRIKE` 的个例损毁型仙蛊（可反复催动的仙蛊走原有扣费路径）。
- 语义：**仙元不足也能出手**——消耗当前全部仙元（归零）、击退一个载体、仙蛊消耗、追加永久道痕标记 `xiangu:daohen:eyes`。
- 仙元为 0 时拒绝（原文没有"零仙元白嫖一击"的依据）；道痕是**追加式账本标记**，重复强催不会叠加第二条。

**服务端 `XianGuService.useForced`** + **命令 `/shengxiangu force <id>`**

前置与普通催动一致（纳气期、已持有、仙窍已成、有载体），但把"仙元不足"从硬拒绝改成可选的强催路径；强催时施加 200 tick 失明（游戏映射：原文只说道痕不可复原，没给时长）。

**道痕复现**：`ApertureTickService` 内，带道痕的角色每 1200 tick 闪一次失明（游戏映射，非原著时长）。

## 顺带修的两个缺陷

1. `TribulationParameters.configuredProfile` 里有一行**重复的 null/blank 检查**（0.3.23 加兜底时没注意原行已存在），已删除。
2. `useForced` 对可反复催动的仙蛊返回通用 `ERROR`（"仙蛊操作失败，记录已保留"——暗示留下记录，实际没有）。0.3.30 实测发现，0.3.31 改为 `NOT_FORCEABLE` 专用文案。

## 未验证 / 边界

- **强催的完整游戏内路径未跑通**：需要纳气期 + 活跃载体，而当前测试角色是 IMMORTAL 终态，且构造纳气期需要本体本命蛊仪式（机器人链路做不到）。领域层与命令分派的验证是充分的，但"扣光仙元 + 失明 + 道痕闪烁"的实际观感未看过。
- 失明时长 200 tick 与道痕复现周期 1200 tick 都是**游戏映射**，原文只给"不可复原"，没有数值。
- 内劫（CANON-012）、余气升炼（CANON-013）仍未实现；一般路线的灾劫目录（GAP-001）与失败处置（GAP-006）仍缺正文，网络取文本轮再次失败（fetch 端点 404、firecrawl 403、搜索只有百科/论坛）。
